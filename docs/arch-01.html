Extract Duplicate Geometry Logic

Consolidate connection point calculations into a shared module

STRONG

Files Involved

Canvas.jsx:201-216 – getConnectionPointCoords()
Connector.jsx:1-16 – duplicate getConnectionPointCoords()
ShapeElement.jsx:100-105 – hardcoded connectionPoints array

The Problem

The same connection point geometry (left, top, right, bottom positions at shape edges) is calculated three separate ways across three files. When connection point behavior changes—moving them to different positions, changing their number, or adjusting hit detection—you must update all three locations simultaneously or risk silent bugs where shapes connect to stale positions.

❌ Deletion test: If you deleted this duplicate, complexity would concentrate in one place. This is a good signal it should be extracted.

The Solution

Create a ShapeGeometry module that owns all shape-related geometry:

// ShapeGeometry.js
export const SHAPE_DIMENSIONS = {
  width: 120,
  height: 80,
};

export function getConnectionPointCoords(shape, pointId) {
  const cx = shape.x + SHAPE_DIMENSIONS.width / 2;
  const cy = shape.y + SHAPE_DIMENSIONS.height / 2;
  
  switch(pointId) {
    case 'left':
      return { x: shape.x, y: cy };
    case 'top':
      return { x: cx, y: shape.y };
    // ... etc
  }
}

export function getConnectionPoints(shape) {
  return [
    { id: 'left', ...getConnectionPointCoords(shape, 'left') },
    { id: 'top', ...getConnectionPointCoords(shape, 'top') },
    // ...
  ];
}

Now Canvas, Connector, and ShapeElement all import from this single module. Geometry changes propagate everywhere automatically.

Benefits

  • ✓ Locality: All connection point geometry lives in one place. When connection points break, look in ShapeGeometry, not 3 files.
  • ✓ Testability: Connection point calculations can be unit-tested independently, then trusted in Canvas/Connector/ShapeElement.
  • ✓ Leverage: When adding new shape types or connection point variants, edit one file instead of three.

Centralize Magic Numbers into Constants Module

Create a single config file for all hardcoded values

WORTH EXPLORING

The Problem

Magic numbers appear 30+ times across 4 files with no explanation:

  • 120 (shape width) and 80 (height) - Canvas, ShapeElement, Connector
  • 8 (hit radius for connection points) - Canvas:223
  • 5 (collision padding) - Canvas:244
  • 50 (curve offset) - Connector:21 – why 50? Never documented.
  • 4000x3000 (canvas size) - Canvas:298
  • 70, 28 (connector label box) - Connector:96-99

When a bug report says "shapes are too hard to click," you don't know if it's the hit radius (8) or collision padding (5). These numbers should have names and comments explaining their origin.

The Solution

Create a constants module that centralizes all configuration:

// constants/CANVAS_CONFIG.js

export const CANVAS = {
  WIDTH: 4000,
  HEIGHT: 3000,
};

export const SHAPE = {
  WIDTH: 120,
  HEIGHT: 80,
  
  // How far outside the shape bounds to detect clicks
  COLLISION_PADDING: 5,
};

export const CONNECTION_POINT = {
  // Radius for hit detection when hovering over a connection point
  HIT_RADIUS: 8,
  
  // Offset for Bézier curve control points (higher = more curve)
  // Determined empirically to give smooth-looking curves
  CURVE_OFFSET: 50,
};

export const CONNECTOR_LABEL = {
  BOX_WIDTH: 70,
  BOX_HEIGHT: 28,
  PADDING: 8,
};

export const COLORS = {
  SHAPE_SELECTION: '#3b82f6',
  CONNECTION_HOVER: '#10b981',
  CONNECTOR_PATH: '#64748b',
};

Benefits

  • ✓ Maintainability: Change hit radius in one place; it updates everywhere.
  • ✓ Discoverability: A new contributor can read CANVAS_CONFIG.js to understand the whole shape system at a glance.
  • ✓ A/B Testing: Easily try different hit radii or curve offsets by swapping constants.

Extract Editing Concerns into Own Module

Separate label editing logic from canvas interaction

WORTH EXPLORING

The Problem

Canvas owns all editing state and behavior:

  • Editing state: editingId, editingText, editingType
  • Handlers: handleShapeDoubleClick, handleConnectorDoubleClick, handleEditSubmit
  • Modal UI: lines 380-401 (handled both shapes and connectors via conditional)

ShapeElement and Connector are just pass-through: they receive editing props, forward double-click to Canvas, wait for Canvas to send back the edited text. When editing breaks, bugs are hard to trace because responsibility is split across 3 files.

The Solution

Create a custom hook + context for editing:

// useEditingMode.js
export function useEditingMode() {
  const [editingId, setEditingId] = useState(null);
  const [editingText, setEditingText] = useState('');
  const [editingType, setEditingType] = useState(null);

  const startEditing = (id, currentText, type) => {
    setEditingId(id);
    setEditingText(currentText);
    setEditingType(type);
  };

  const submitEdit = (onSave) => {
    if (editingId) onSave(editingId, editingText);
    clear();
  };

  const clear = () => {
    setEditingId(null);
    setEditingText('');
    setEditingType(null);
  };

  return { 
    editingId, 
    editingText, 
    editingType,
    setEditingText,
    startEditing, 
    submitEdit, 
    clear,
    isEditing: editingId !== null
  };
}

// EditingModal.jsx - owns the modal UI
export function EditingModal({ editing, onShapeSave, onConnectorSave }) {
  if (!editing.isEditing) return null;

  const handleSubmit = () => {
    if (editing.editingType === 'shape') {
      onShapeSave(editing.editingId, editing.editingText);
    } else if (editing.editingType === 'connector') {
      onConnectorSave(editing.editingId, editing.editingText);
    }
    editing.clear();
  };

  return (
    <div className="edit-modal-overlay" onClick={editing.clear}>
      <div className="edit-modal">
        <h3>Edit Label</h3>
        <input
          value={editing.editingText}
          onChange={(e) => editing.setEditingText(e.target.value)}
          onKeyDown={(e) => {
            if (e.key === 'Enter') handleSubmit();
            if (e.key === 'Escape') editing.clear();
          }}
        />
        <button onClick={handleSubmit}>Done</button>
      </div>
    </div>
  );
}

Benefits

  • ✓ Locality: All editing logic—state, modal UI, handlers—lives in useEditingMode + EditingModal, not scattered across Canvas, ShapeElement, Connector.
  • ✓ Testability: useEditingMode can be tested without rendering Canvas or ShapeElement.
  • ✓ Reusability: Other diagram tools can reuse useEditingMode + EditingModal.

Document and Test Fragile Geometry Functions

Add comments and unit tests for magic numbers in path generation and hit detection

WORTH EXPLORING

The Problem

Three functions hide unexplained behavior:

  • isPointInShape() – line 244

    Adds 5px padding on all sides for collision detection. Why 5? Never documented. Changes here affect shape selectability but no comment explains it.

  • generateCurvedPath() – line 21

    Offsets control points by 50px. Why 50? No explanation. Empirically determined? This affects curve smoothness but is invisible.

  • getPathMidpoint() – line 27

    Parses SVG path string by array index: parts[1], parts[5], parts[6]. If generateCurvedPath() changes format, this breaks silently.

The Solution

Add inline documentation + unit tests:

// Canvas.jsx
const isPointInShape = (point, shape) => {
  const SHAPE_WIDTH = 120;
  const SHAPE_HEIGHT = 80;
  // Hit detection padding: expand shape bounds by 5px to make small shapes 
  // easier to click. This is tuned for 13" laptop screens at 100% zoom.
  // If you change this, run the hit-detection test suite.
  const COLLISION_PADDING = 5;

  return (
    point.x >= shape.x - COLLISION_PADDING &&
    point.x <= shape.x + SHAPE_WIDTH + COLLISION_PADDING &&
    point.y >= shape.y - COLLISION_PADDING &&
    point.y <= shape.y + SHAPE_HEIGHT + COLLISION_PADDING
  );
};

// Connector.jsx
const generateCurvedPath = (startCoord, endCoord) => {

  // diagram shapes. Higher values = more curve; lower = straighter.
  // Tested against shapes 200-400px apart. Adjust if adding long/short connectors.
  
  const cp1x = startCoord.x + offsetY;
  // ...

// Unit test for path parsing
test('getPathMidpoint extracts correct coordinate from generated path', () => {
  const path = 'M 0 0 C 50 0 150 0 200 100';
